# 交接单样例（**代码渲染出来的**）

> 🔴 **这份文件是生成的，不要手改** —— `uv run python -m experiments.render_handoffs`
> 手写的样例必然陈旧，而那是「改一句文案、下游静默失效」的另一种形态（这次下游是文档）。
> 数据和渲染已经分层了，样例就能**生成**：渲染器改一次，重跑一次。


## 形式（四条，`proto/handoff/__init__.py` 里定的）

    段名 0 列（独占一行）· 来源 2 列 · 段体 2 列 · 每层 +2

**渲染只有一条路**：`render_hop(hop, sections)` —— 段名从 `SECTION` 取、
来源从 `SOURCE_NOTE` 取、**顺序从 `HOPS[hop]` 取**、缩进用 `BODY`。
没有第二种写法，也就没有"两套"可失配。

守卫：`evals/unit_handoff_form.py`（41 条）—— 其中第 ⑤ 条**扫源码**：
段名行不许手拼，只许从 `SECTION` 取。

## 🔴 什么算「交接单」——**只有下面第一类**

> 用户 2026-11-05：*"我们现在既然澄清了哪些是所谓的**交接清单**，
> 你就应该在文档里纠正以前的误区啊，不然下次又出现理解上的偏差。"*

| 类 | 是什么 | 有单子吗 | 例 |
|---|---|---|---|
| **① 交接单** | 平台**按形式排**出来的一段文本 | ✅ **走 `render_hop`** | 任务文本 · 交接书 · 回执 · 台账 · 试答 · 推回去 · 透传 |

### 6. 回执 · fault（**平台故障**）

`H10`

⚠️ **独立出口**：这一轮**根本没跑成**，与「执行器干不了」是两回事 —— 所以不借 failed 的文案（「推了 N 轮」对故障是假话），也不塞进【执行器说】。

```
【交付】
  ⚠️ 没跑成 —— **平台故障**（重试过一次仍失败）
【下一步】
  这次是**平台故障**，**不是任务本身的问题** —— 原样再 `delegate` 一次即可。
【平台故障】
  这一轮**根本没跑成**：TimeoutError: 网关抖动
  平台侧的基础设施抖动，**重试过一次仍然失败** —— 不是任务本身的问题，也不是执行器没干成。
  **原样再 `delegate` 一次**即可（不用改措辞、不用改参数、不用问用户）。
```

### 11. 推回去（平台 → 执行器）

`H7`


### 12. 决策（LLM 调用 → 记录）★ **一次 LLM 调用的两端**

`—`

⚠️ **它原来有自己的一套段名**（`前提`/`问题`/`结果`/`下一步`，**不带 `【】`**）和**自己的一套缩进**（4 格）—— 把「段名一律 `【…】` 独占行首」那条硬规矩**开了口子** ✗。按用户 2026-11-05 定的判据（*「所谓交接，就是外部给 LLM 什么东西、LLM 吐出什么东西」*）它是**交接**：**结果那一格是 LLM 吐的**，所以**只有它标来源**，另三格是平台的话。

```
【前提】
  - 执行器申报要的信息（`ask_user` 参数原话，132 字）：这节课希望侧重哪种上法？
  - 它最后说的那段（78 字，可能有上下文、也可能只是过场）
【问题】
  **主 agent 的上下文里**，有没有执行器要的那个信息？
【结果】
  来源：**它说的** —— LLM 的输出，原样
  - can_answer = **False**
  - 补充：（无）
【下一步】
  答不上 → 登记待答，由**平台**把执行器原话**透传**给用户
```
