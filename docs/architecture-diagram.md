## 一、架构图：主 agent 是完整的 agent

```
     ┌───────────────────────────────────────────────────────────────────────┐
     │  ① Skill —— 专业能力（静态 · 可版本化）                                │
     │     每项只有 description + instructions                                │
     │     ⚠️ 无参数声明 · 无交付物声明 · 无结果协议 · 无完成条件             │
     └───────────────────────────────────┬───────────────────────────────────┘
                                         │ instructions（delegate 时交给执行器）
    用户原话 ─┐                          │  ★ 也是判定"完成了没"的依据
              │                          │
              ▼                          ▼
┌──────────────────────────────────────────────────────────────────────────────┐
│  ② 主 agent —— **一个完整的 agent**（自己的工具 + 自己的循环）                 │
│                                                                              │
│     循环：LLM 思考 → 调工具 → 看结果 → 再思考 → … → 输出                     │
│                                                                              │
│     三条出路，**它自己选**：                                                   │
│       · 直接答            —— 闲聊 / 追问 / 澄清（**不建 Task**）              │
│       · write_artifact    —— 自己产出短内容（**不建 Task**）                  │
│       · delegate(...)     —— 需要专业能力时（**建 Task**）                    │
│                                                                              │
│     上下文里：对话历史 + 【平台提示】任务台账（prepare 注入，含进度/缺失项）   │
└───────────────┬──────────────────────────────────────────────────────────────┘
                │ delegate(skill_name, task)
                ▼
     ┌──────────────────────────────────────────────────────────────────────┐
     │  ③ delegate 工具内部 —— **平台代码，这几步是保证的**                   │
     │                                                                      │
     │   ⓪ 同 skill 下未了结的旧 Task → 标记 **superseded**（防台账挂过期项） │
     │                                                                      │
     │   ① 调执行器（隔离上下文，内部最多 react 3 轮，见 §二）                │
     │        │                                                             │
     │        ├─ completed ──────────────────────► 交付（落库 / 正文）       │
     │        │                                                             │
     │        └─ waiting_for_input                                          │
     │              ↓                                                       │
     │   ② **平台强制先让主 agent 试答**（用它的完整上下文 + 进度 + 缺失项）  │
     │        ├─ 答上了 → 带补充重新调执行器                                 │
     │        │     ├─ completed ──────────────► 交付                       │
     │        │     └─ 还是没完成 → 往下走                                   │
     │        └─ 答不上 → 往下走                                             │
     │              ↓                                                       │
     │   ③ **登记待答**（stage = waiting_for_input），交给主 agent 去问用户   │
     │                                                                      │
     │   （执行器跑了 3 轮仍是 incomplete → stage = **failed**，交给主 agent）│
     └──────────────────────────────┬───────────────────────────────────────┘
                                    ▼
     ┌──────────────────────────────────────────────────────────────────────┐
     │  ④ Sub Agent —— 可选执行者（按需创建 · 通用 · **不绑 skill**）         │
     │     平台约定只有一句：「要交付成文件的内容 → write_artifact」          │
     │     ⚠️ 缺信息时**明确说明需要什么**（不说"向用户提问"——它不知道有主 agent）│
     └──────────────────────────────┬───────────────────────────────────────┘
                                    ▼
     ┌──────────────────────────────────────────────────────────────────────┐
     │  ⑤ 产物库                                                            │
     │     ⚠️ 原型是内存 dict，**生产要换真存储**                            │
     └──────────────────────────────────────────────────────────────────────┘
```

## 二、`run_task` 内部：判定 + 出口限制

```
run_task（最多 MAX_REACT_ROUNDS = 3 轮）
  │
  │  ① 执行器干活（隔离上下文）
  │  ② 判定：**任务完成了吗**（三态）
  │       completed          → 出口，返回
  │       waiting_for_input  → 出口，返回
  │       incomplete         → **不让它停**：
  │            ├─ 还有轮次 → 带上 progress/missing **推回去继续**
  │            └─ 推满了   → 显式结束，交给主 agent
  ▼
ExecOutcome { status, artifacts, report, rounds, progress, missing }
```

**判定的三个要点**（全是实测踩出来的，详见 `solution.md` §十一）：

1. **问"任务完成了没"，不是"产物生成了没"** —— 产物只是证据之一
2. **必须把 `instructions` + `given` + 产出 + 产物数量都带进提示词** ——
   判定看不到它需要的信息，就只能猜（**这个坑踩过两次**）
3. **规则要列举具体的失败形态**（"占位/待补充/半成品"），不要用"符合要求"这种笼统说法

**推回去的提示词**（把判定吐出的信息都喂回去）：

```
任务还没完成。

**你已经完成了**：导学单内容已设计完成，包含学习目标、预习任务、当堂检测三部分
**还缺**：
- 缺少导学单文件产物：内容已设计好，但未实际写入产物库

请**接着往下做**，不要从头再来。
如果确实缺少必要信息才能继续，就**明确说明你需要什么**…
```

## 三、`Task.stage`（5 态）

```
                delegate 建 Task
                      │
                      ▼
              ┌───────────────┐
              │   running     │
              └───────┬───────┘
                      │
        ┌─────────────┼─────────────┐
        │             │             │
   completed   waiting_for_input   failed
   （交付）      （等用户答复）      （推满 3 轮仍 incomplete）

   另有 superseded：同 skill 被重新委派时，旧的自动标记（**不用管了**）
```

| 状态 | 含义 | 台账里 |
|------|------|--------|
| `running` | 正在执行 | 一行 |
| `completed` | 已完成 | 一行（含产物 ID） |
| `waiting_for_input` | 等用户答复 | **展开**：进度 / 缺失项 / 执行器原话 |
| `failed` | 失败（交给主 agent） | **展开**：同上 |
| `superseded` | 被新的委派取代 | 一行 |

**与 `_Judgement.status` 的关系**：前三个**同名**，唯一映射 `incomplete → failed`。

**暂未实现的三个**（记清了为什么不做、什么时候该做）：
- `pending` —— 建 Task 就立刻派发，没有"创建了还没跑"的窗口（等「计划-执行分离」）
- `waiting_for_dependency` —— `delegate` 是**同步**的，依赖在主 agent 循环里天然解决（等「异步委派」）
- `cancelled` —— 需要给主 agent 新工具，场景**尚未实测到**（等真遇到）

## 四、一次完整运行（真实模型实测）

```
用户：帮我备课
  │
  ├─ prepare   无台账（首次）→ 不注入
  ├─ agent     信息太少 → 先问（**Task = 0**）
  └─ finalize  无待答 → 不补

用户：分数的初步认识
  │
  ├─ agent     判断能推进 → 🧠 调 delegate(lesson-prep)
  │             ↓
  │           执行器读 skill 指令，发现缺「课时」→ **waiting_for_input**
  │             ↓
  │           平台强制主 agent 试答 → 答不上
  │             ↓
  │           stage = waiting_for_input，主 agent 问用户：
  │           "执行器按人教版三年级上册处理了，需要你确认一个关键信息" ✅
  │
用户：第1课时
  │
  ├─ prepare   注入台账（含"已做到/还缺"）
  ├─ agent     重新 delegate → 旧的自动 **superseded**，新的 **completed** ✅
  │            → "备课搞定了。需要的话我还可以帮你出导学单和随堂小测，要一起做吗？"
  │                                                    ↑ 保守范围：**只提一句，不直接做** ✅
  └─ finalize  无待答 → 不补
```

## 五、关键细节清单

| # | 细节 | 位置 | 为什么重要 |
|---|------|------|-----------|
| 1 | **主 agent 是完整 agent** | `agent.build_agent` | 要能"直接答"，不能凡 skill 必委派 |
| 2 | **技能活一律委派**（无 `load_skill`） | `agent._MAIN_PROMPT` | 实测：给了它自己干的路，隔离全丢 |
| 3 | **平台不抽取参数** | 用户原话原样带给执行器 | 自然语言千变万化，规则/schema 都不可靠 |
| 4 | **完成 = 三态判定**，不是"产物库非空" | `executor._judge` | 产物只是证据之一 |
| 5 | **判定提示词必须带全上下文** | 同上 | `instructions` + `given` + 产出 + 产物数，**缺一不可** |
| 6 | **出口限制**：incomplete 推回去 | `executor.run_task` | 执行器没干完是**它的问题**，不转嫁给用户 |
| 7 | **`progress`/`missing` 一路传到主 agent** | `agent._outcome_note` | 主 agent 才知道该重派还是该问用户 |
| 8 | **`delegate` 内部保证"先试答"** | `agent._ask_main` | 平台代码，LLM 跳不过 |
| 9 | **Task 只在委派时建** | `agent.delegate` | 不委派就没有 Task |
| 10 | **`superseded`**：同技能重新委派自动取代 | `agent._supersede_old` | 防台账挂过期项 |
| 11 | **`tasks` 按 id 合并的 reducer** | `graph._merge_tasks` | 并行 delegate 会互相覆盖 |
| 12 | **task id 取 `tool_call_id` 尾部** | `agent.delegate` | 取前 6 位会撞车 |
| 13 | **台账注入**（prepare） | `graph.node_prepare` | 不注入，主 agent 看不见"已派过什么" |
| 14 | **兜底补问**（finalize） | `graph.node_finalize` | 保证待答不丢 |
| 15 | **不传 config 给执行器** | `executor.run_task` | 传了会变成独立根图 |
| 16 | **不写草稿** | — | 接受重跑，换掉"草稿 vs 成品"一整类 bug |
| 17 | **每个 LLM 调用点都兜底** | `llm.safe_structured` | 实测 DashScope 偶发 grammar 超时，一次抖动炸掉整轮 |
| 18 | **决策一律用 `with_structured_output`** | 三处判定 | 不用工具参数传决策（反面教材：`finish` 工具） |
| 19 | **平台管机制，skill 管业务** | `_MAIN_PROMPT` + skill 的 `instructions` | "哪些参数必答"是业务判断，平台不猜 |
| 20 | **产出范围以用户明确说的为准** | `_MAIN_PROMPT` | 用户说"备课"就只出教案，想提供别的**只提一句** |

## 六、程序强制 vs 行为建议

**判据**：**被违反了会导致"状态不一致"的 → 程序强制；只是"效果差一点"的 → 行为建议。**

| 🔴 程序强制（12 条） | 🟡 行为建议（6 条） |
|---|---|
| 产物必须真实存在（编 ID 无效） | 缺信息要**明确说明**需要什么 |
| 执行器不许无限跑（3 轮上限） | 不要用「已完成」糊过去 |
| 状态字段由代码写 | 判定的三条规则 |
| 三态穷举分派（没有第四种） | 不要一律问 / 产出范围以用户为准 |
| 同技能旧的待答自动取代 | **"你需要知道 X"写在 skill 的 `instructions`** |
| 待答不丢（finalize 兜底） | 交付物用 `write_artifact` 落库 |
| LLM 调用失败有保守默认值 | |
| 并行不互相覆盖（reducer） | |
| 试答只做一次 | |
| task id 不撞车 | |
| 主 agent 试答是强制的（工具内部） | |
| 图结构固定（prepare → agent → finalize） | |

## 七、与最初版本的对比

| | 最初（workflow 版） | **现在** |
|---|---|---|
| 主 agent | 纯路由器（只有 `llm_pick` + 试答） | **完整的 agent**（工具 + 循环） |
| 流程 | 代码写死的固定边 | **由 LLM 驱动** |
| 闲聊"你好" | ❌ 返回"（无产出）" | ✅ 自己答 |
| 建 Task 时机 | 选完技能**必建** | **决定委派才建** |
| 完成判定 | `ExecResult.status`（执行器**声称**） | **三态判定**（问"任务完成了没"） |
| 交付物声明 | `deliverables` 清单 + `required` | **不需要** |
| 参数 | 动态 schema 抽取 + 并集计算 | **不抽取**，原话原样带进去 |
| 挂起 | `interrupt()` + `Command(resume)` | **不需要**（`waiting_for_input` 由 Task 推导） |
| 问参数 | 规划阶段提前问 | **运行时**：先问主 agent，再问用户 |
| Task 状态 | 无 | **5 态**（含 `superseded`） |
| `Skill` 字段 | name/description/instructions/**params**/**criteria** | **只剩 description + instructions** |
| 决策输出 | 混着（工具参数 / 自然语言） | **一律 `with_structured_output`** |
